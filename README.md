# WORLD 2050 — 세계 평화 협상 시뮬레이터

고등학교 SLAT 자율활동용 실시간 멀티플레이 교육 웹게임입니다. 학급마다 게임방을 만들고, 학생들은 6개 가상 국가의 대표단이 되어 5라운드 동안 자원을 거래하고 협상하며 세계 평화 협약을 만듭니다.

- 학생: 회원가입 없이 **방 코드 + 국가 참가 코드**로 입장 (스마트폰·태블릿·노트북)
- 교사: 비밀번호로 보호되는 관리 화면에서 방 생성, 라운드 진행, 사건 발동, 복구, 결과 내보내기
- 전자칠판: `/board/방코드` 전체 화면 세계 현황판

## 빠른 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
```

```bash
npm run build
```

```bash
TEACHER_PASSWORD=원하는비밀번호 npm start
```

브라우저에서 `http://localhost:8080` (학생), `http://localhost:8080/teacher` (교사)를 엽니다.
개발 중에는 `npm run dev` (서버 8080 + Vite 5173, 코드 변경 시 자동 반영)를 사용합니다.

## 환경변수

| 이름 | 설명 | 기본값 |
| --- | --- | --- |
| `TEACHER_PASSWORD` | 교사용 관리자 비밀번호. **반드시 설정**하세요. 없으면 실행할 때마다 임시 비밀번호를 만들어 서버 로그에 출력합니다. | (임시 생성) |
| `SESSION_SECRET` | 교사 로그인 토큰 서명용 비밀값. 비우면 데이터 폴더에 자동 생성·보관합니다. | (자동) |
| `PORT` | 서버 포트 | `8080` |
| `DATA_DIR` | 게임 데이터 저장 폴더. 배포 시 **영구 디스크** 경로로 지정하세요. | `./data` |

## 구조

```
shared/   게임 규칙 (서버·클라이언트 공용)
  data.ts      국가·행동·라운드 사건·협약 조항 등 수치 데이터  ← 균형 조정은 여기서
  content.ts   세계 시민 지식 카드, 퀴즈
  engine.ts    규칙 엔진: 라운드 진행, 거래 검증, 협약 집계, 평화 지수·점수 계산
  types.ts
server/index.ts   Express + WebSocket 서버 (인증, 방 관리, 자동 저장, 타이머)
client/src/       React + TypeScript + Tailwind CSS
  pages/       Home(입장) · Student(학생) · Teacher(교사) · Board(전자칠판)
  components/  World(지도·평화 지수·뉴스) · Learn(지식 패널·퀴즈·규칙) · Report(보고서)
scripts/      test-engine.ts(규칙 테스트) · loadtest.ts(다중 접속 통합 테스트)
```

### 실시간·안정성 설계

- **서버 권위**: 모든 게임 상태는 서버 메모리에 있고, 클라이언트는 명령만 보냅니다. 규칙 검증은 전부 `shared/engine.ts`에서 서버가 수행합니다.
- **원자적 거래**: 명령은 한 번에 하나씩 처리됩니다. 승인 시점에 양쪽 자원을 다시 확인하고, 실패하면 실행 전 상태로 되돌립니다. 중복 승인·음수 자원이 발생하지 않습니다.
- **중복 요청 방지**: 요청마다 고유 id를 붙여 재전송·더블 클릭을 한 번만 실행합니다.
- **자동 저장·복구**: 상태가 바뀔 때마다 `DATA_DIR/rooms/방코드.json`에 저장하고, 라운드 시작 시점마다 복구용 스냅샷을 남깁니다. 서버가 재시작되어도 게임이 이어집니다.
- **재접속**: 학생 기기에는 임의 토큰만 저장됩니다. 새로고침·네트워크 끊김 후 자동으로 같은 국가에 복귀합니다.
- **권한**: 교사 명령은 서명된 토큰이 있는 연결만 실행할 수 있고, 국가 정책·거래·투표는 해당 국가의 대표 1명만 실행할 수 있습니다. 참가 코드·성찰·퀴즈 답안은 다른 사용자에게 전송되지 않습니다.
- **개인정보**: 닉네임(선택) 외에는 수집하지 않습니다.

### Supabase 대신 Node 서버를 쓴 이유

요청서의 "Supabase 또는 동등한 실시간 서버" 가운데 단일 Node 서버를 선택했습니다. 약 260명 규모에서는 프로세스 하나로 충분하고, 거래의 원자성과 라운드 타이머를 서버 한 곳에서 단순하게 보장할 수 있으며, 학교 내부망 PC에서도 그대로 실행할 수 있기 때문입니다. 단, **서버 인스턴스는 반드시 1개**로 운영해야 합니다(여러 대로 수평 확장하면 방 상태가 나뉩니다).

## 테스트

```bash
npm test
```

규칙 테스트 8종과 "각자도생 / 협력" 두 가지 전체 플레이 시뮬레이션을 실행합니다. 협력 없이는 공동 승리가 불가능하고 협력하면 가능한지 확인합니다.

```bash
TEACHER_PASSWORD=서버와같은값 npm run loadtest
```

실행 중인 서버에 9개 방 × 30명(총 270명 + 교사·칠판 18개 연결)을 실제 WebSocket으로 접속시켜 동시 거래, 중복 승인, 재접속, 라운드 종료 직전 제출, 방 독립성, 복구 기능을 검증합니다. (약 1분 30초 소요, 테스트용 방은 끝나면 삭제됩니다.)

개발 환경에서 확인한 결과: 288개 동시 연결에서 방 내 상태 동기화 지연 약 50ms 이내, 서버 메모리 약 90MB.
이 수치는 한 대의 컴퓨터 안에서 측정한 것이므로, **실제 학교 와이파이에서는 수업 전에 반드시 리허설**을 해 보세요.

## 배포

WebSocket을 지원하고 영구 디스크를 붙일 수 있는 곳이면 어디든 됩니다. `Dockerfile`이 포함되어 있습니다.

### Docker (Render, Railway, Fly.io, 학교 서버 등)

```bash
docker build -t world2050 .
```

```bash
docker run -d -p 8080:8080 -e TEACHER_PASSWORD=원하는비밀번호 -v world2050-data:/data world2050
```

- 인스턴스 수는 **1개**로 고정하세요. (자동 확장 끄기)
- `/data`에 영구 디스크(볼륨)를 연결하세요. 연결하지 않으면 서버가 재배포·재시작될 때 게임 기록이 사라집니다.
- 무료 요금제 중 일정 시간 뒤 잠드는 서비스는 수업 중 끊길 수 있으니 피하세요.
- 권장 사양: vCPU 1개, 메모리 512MB 이상.
- HTTPS(wss)는 호스팅 서비스의 프록시가 처리합니다. 상태 확인 주소는 `/api/health`입니다.

### 교내 PC에서 직접 실행

같은 네트워크의 PC 한 대에서 `npm start`를 실행하고, 학생들은 `http://그PC의IP:8080`으로 접속합니다. PC 방화벽에서 8080 포트를 허용해야 하며, 학교 와이파이가 기기 간 통신을 막는 경우에는 사용할 수 없습니다.

## 알려진 한계

- 보고서 PDF는 브라우저의 인쇄 기능("PDF로 저장")으로 만듭니다. 별도의 PDF 파일 생성 서버는 없습니다.
- 글꼴(Pretendard)은 CDN에서 불러옵니다. 차단된 네트워크에서는 기기의 기본 한글 글꼴로 표시됩니다.
- 교사 계정은 비밀번호 하나를 공유하는 방식입니다. 교사별 계정 분리가 필요하면 `server/index.ts`의 로그인 부분을 확장하세요.
- 실제 기기 260대를 동원한 현장 테스트는 하지 않았습니다. 위 부하 테스트는 한 컴퓨터에서 만든 가상 접속입니다.

교사용 운영 안내는 [docs/교사용_운영_매뉴얼.md](docs/교사용_운영_매뉴얼.md)를 보세요.
